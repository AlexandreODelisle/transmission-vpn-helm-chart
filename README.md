# Servarr suite deployment

## Objective

Simplify the deployment of the *arr suite for media content management in a self-hosted envrionment.

## Limitations

* The chart uses `nfs v4` to mount the librairies from the NAS into the Pods.

## Exposing the service
This chart deployment is built to use `HTTPRoute` or `Ingress` to expose the services, but the TLS of the service are typically handled by `cert-manager` that is not set as a dependencies it the current chart.

## Configuration of the services

* There is no implemnetation of `buildarr` to handle the configuration of the `indexers`, and inter relationship of the services. The configuration needs to be done by the user.
* The service is build to run using `CloudNativePG`, and currently the operator needs to be installed prior to the deployment.
* The service currently use `external-secret-operator` to fetch secrets or allows the creation of `Secret`.

```bash
helm install servarr servarr/transmission
```

## Installing the Chart
To install the chart with the release name `transmission`:
```bash
helm install transmission servarr/transmission
```

### Custom Resources
If external-secret-operator Helm Chart and CRDs is not installed you can enabled it within the values.

## Uninstalling the Chart
To uninstall the `transmission` deployment:
```bash
helm uninstall transmission
```
The `PersistentVolumeClaim` and `PersistentVolume` may hang.
